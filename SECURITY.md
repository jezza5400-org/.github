# Security Policy

We take security seriously and appreciate responsible disclosure of vulnerabilities.

---

## Reporting a Vulnerability
If you discover a security issue, please report it privately:

**Email:** jeremy_sprague@outlook.com
**Do not** open public GitHub issues for security concerns.

Provide:
- Description of the vulnerability  
- Steps to reproduce  
- Potential impact  
- Any suggested remediation  

We will acknowledge receipt and follow up promptly.

---

## Supported Versions
Security fixes are applied to:
- `main` branch  
- Active, supported releases of production systems  

Older or archived repositories may not receive patches.

---

## Security Best Practices for Contributors
- Never commit secrets, tokens, passwords, or certificates.
- Use environment variables or secret‑management tools.
- Keep dependencies updated and avoid unmaintained packages.
- Follow internal guidelines for secure coding and architecture.
- Ensure CI security scans pass before merging.

---

## Disclosure Policy
We follow a responsible disclosure model:
- We investigate all reports.
- We work with reporters to validate and resolve issues.
- We publish security advisories when appropriate.

Thank you for helping keep our organisation secure.
